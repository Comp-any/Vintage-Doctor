== Mods getting in each other's way, or their own ==
✖ Doctor Sick: 2 block(s) or item(s) need code that isn't in the game (DoctorGhostItem, DoctorGhostBehavior, DoctorGhostBlock, DoctorGhostEntity)
  doctorsick:ghost (its code: DoctorGhostItem)
  doctorsick:ghost (a behaviour: DoctorGhostBehavior)
  doctorsick:ghostblock (its code: DoctorGhostBlock)
  doctorsick:ghostblock (its data code: DoctorGhostEntity)
  Each of these names a piece of code that should make it work, and no loaded mod has that code: the mod's own code didn't load, it needs another mod that isn't installed, or this version of the mod doesn't match its files. They are in the game but act like plain blocks and items: machines don't open, tools don't do their job.
  → Update the mod and install every mod its page lists as required. For a mod of your own: the name in the file has to be exactly the one given to RegisterBlockClass, RegisterItemClass or RegisterBlockEntityClass.
  Doctor Sick's page (/doctor mod doctorsick)
⚠ Doctor Sick: 1 block(s) or item(s) couldn't be added to the game
  doctorsick:ghost
  The game refused them while loading. Most often something with the same name was already there: two mods, or two files of one mod, add a thing with the same name, and only the first one exists. The log has the game's reason for each.
  Doctor Sick's page (/doctor mod doctorsick)
⚠ Doctor Sick: 1 of its files couldn't be read, so what they describe isn't in the game
  doctorsick:itemtypes/broken.json
  Each of these files has a mistake in it (most often a missing comma or bracket) or uses something this version of the game doesn't know, and the game skipped the whole file: the blocks, items or recipes in it don't exist. The mod's page has the game's own error for each, with the place.
  Doctor Sick's page (/doctor mod doctorsick)
⚠ Doctor Sick tries to change 1 file(s) that aren't there
  game:itemtypes/doctor-no-such-file.json
  A patch changes one thing inside another file. These files don't exist in this version of the game (or of the mod they belong to): they were renamed, moved or removed in an update, and the mod hasn't caught up. Whatever those patches were for doesn't happen.
  Doctor Sick's page (/doctor mod doctorsick)
• Doctor Sick has 1 patch(es) for mods that aren't installed (doctornosuchmod)
  That is how one mod supports another, and harmless: the game writes each one into the log as an error, but nothing is missing.
⚠ doctorsickshared has code in it (SickShared.dll) but calls itself a content mod, so the game leaves the code out
  The game only runs code from mods whose modinfo.json says "type": "code". Whatever this mod's code was meant to do doesn't happen; its blocks, items and recipes still load.
  → Tell the mod's author. Changing the type to "code" in the modinfo.json inside the zip puts it right.
  doctorsickshared's page (/doctor mod doctorsickshared)
⚠ doctorsickbundled has code in it (0Harmony.dll, SickShared.dll) but calls itself a content mod, so the game leaves the code out
  The game only runs code from mods whose modinfo.json says "type": "code". Whatever this mod's code was meant to do doesn't happen; its blocks, items and recipes still load.
  → Tell the mod's author. Changing the type to "code" in the modinfo.json inside the zip puts it right.
  doctorsickbundled's page (/doctor mod doctorsickbundled)
⚠ doctorsickslash has 1 block and item file(s), but none of its blocks or items are in the game
  Some Windows tools write folder separators the wrong way round into a zip. Windows reads them anyway; Linux and macOS see one long file name instead of folders, so the mod has no blocks, items or textures.
  Repack doctor-sick-backslash.zip the right way (the original is kept) (/doctor fix doctor:repack 0/doctor-sick-backslash.zip)
  doctorsickslash's page (/doctor mod doctorsickslash)
• doctorsickbundled brings its own copy of 0Harmony.dll, which the game already has.
  Only one copy of a code library can be in use, and the game's own comes first. A mod's copy is at best ignored; when it is a different version, the mod fails with "method not found" or "could not load file or assembly".
  Take the game's libraries out of doctor-sick-bundled.zip (the original is kept) (/doctor fix doctor:strip-libraries 0/doctor-sick-bundled.zip)
  doctorsickbundled's page (/doctor mod doctorsickbundled)
• SickShared.dll is in more than one mod: doctorsickshared, doctorsickbundled.
  The game loads a code library by name once. Whichever mod loads first decides the version; the other gets that copy too, and fails if it needed a different one.
⚠ 2 file(s) are replaced by more than one mod: only one copy of each is used
  doctorsick:config/note.json: doctorsickold, Doctor Sick
  game:recipes/grid/anchor.json: Doctor Sick, doctorsickold
  When two mods ship the same file, the game takes one and drops the other without a word. One of these mods isn't doing all it was meant to. Which one wins depends on the order the game loads them in.
  → Check both mods' pages for a note about each other. If they do the same job, keep one. Mods that change a file with a patch instead of replacing it can work side by side.
• Doctor Sick replaces 1 of the game's own files outright
  game:recipes/grid/anchor.json
  A mod can change a file of the game with a patch (one value) or by shipping its own copy of the whole file. A whole copy also throws away whatever the game's updates and other mods' patches changed in that file, so it is the first thing to look at when something else stops working.
⚠ 1 mod(s) made for an older game replace 1 of the game's own files (the game is 1.22.7)
  doctorsickold (made for 1.19.0): 1 file(s)
    game:recipes/grid/anchor.json
  These mods ship whole copies of the game's files as they were in an older version. Everything the game has changed in those files since is undone: recipes and items that went missing, things from the update that don't work, shaders that give a black screen or stop the game from starting.
  → Look for an update of each. If something from the last game update is missing or broken, try without these mods first.
  doctorsickold's page (/doctor mod doctorsickold)
⚠ 1 mod(s) with code were made for an older game than 1.22.7 and have errors now: Doctor Crashy (1.20.0)
  Mods that add code are built against one version of the game. After a game update most keep working, but when one of them has errors, the version is the first suspect.
  → Update these first. If there is no update, the mod's page or comments usually say whether it works on this version.
  Doctor Crashy's page (/doctor mod doctorcrashy)
⚠ 1 recipe(s) have exactly the same ingredients as another recipe that makes something else
  Flint (game:flint), Stick (game:stick):
    Flint (game:flint) ×2  (Doctor Sick, recipes/grid/shadow-b.json)
    Stick (game:stick) ×2  (Doctor Sick, recipes/grid/shadow-a.json)
  The crafting grid can only offer one result for one set of ingredients, so only one of each pair can ever be crafted. This happens when two mods each add a recipe without knowing of the other.
  → Many mods can switch single recipes off in their config. Otherwise tell both authors: one of them has to change an ingredient.
